## 核心操作（按用户实际使用排序）

1. **打开首页到地球能用**：导航开始 → Cesium 画布出现且底部 Dock（图源/流星雨/版本更新按钮）可交互。这是唯一主口径操作。
2. （次要）城市照片画廊打开与翻页——当前媒体库为空，无真实数据可测，本周期只做确定性验证（缓存头）与结构性分析，不做配对计时。

## 「能用」的判定（bench --ready 表达式）

```js
!!document.querySelector('canvas') && !!document.querySelector('[aria-label="版本更新"]')
```

画布 + Dock 按钮同时存在才算能用；骨架/空壳不算。

## 不可动的红线

- 视觉、交互、功能零变化（流星雨、星空、日夜切换、相机动画必须原样）。
- 不改任何用户可感知行为。
- **合并卫生（本项目特有硬约束）**：本 fork 每周由 GitHub Actions 自动合并上游
  Aisland-SJL/StarMap。禁止大面积改写源码文件；每处手术必须最小 diff、
  优先集中在少数文件，凡"要改十几个文件才安全"的方案一律降级为建议项。

## 测量口径

- 主口径：`bench.py --profile fast4g --cpu 1`，冷缓存，≥10 次，报 p50/p75/p95。
- 附：`--profile none` 一组，反映 Mac mini 本机真实（不限速）体验。
- 确定性计数：构建产物 JS 字节数与文件数、页面加载请求数、长任务总时长、
  /media/user/ 二次访问是否命中缓存（curl -I 头 + 浏览器 network 计数）。

## 棘轮与护栏（改代码前先跑绿）

- `npm run lint` 与 `npm run build:public`（项目自带门禁）必须绿。
- 视觉回归：优化前后同尺寸截图（1440×900）比对。
- 功能冒烟：首页加载、图源切换到 Cesium、版本更新页打开。
- 棘轮：基线 p75 与 dist JS 总字节记入 `perf/bench/`，只许变好。

## 上线与回滚

- 所有优化以独立 commit 落在本地 main；**不自动推送**（AGENTS.md 要求显式批准），
  推送命令在报告中给出。回滚 = `git revert` 对应 commit。
- 每周上游自动合并是既定流程，优化 commit 必须能与之共存。
